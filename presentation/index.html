Introduction to Compiler Design

Compilers translate high-level programs into executable form.

A compiler reads source code, checks its structure and meaning, then produces target code that a machine or runtime can execute.

This project focuses on the first major stage: lexical analysis.

  • Reads the raw program text.
  • Breaks text into meaningful symbols.
  • Prepares clean input for later compiler phases.
  • Reports unknown characters when input is not recognized.

What is Lexical Analysis?

Lexical analysis converts characters into tokens.

Input x = 5 + 10;
Process

Scan the input from left to right and group characters by rules.

Output

A sequence of categorized tokens such as identifiers, operators, numbers, and special characters.

Role of the Lexer in Compiler Phases

The lexer is the compiler's first filter.

Source CodeRaw characters

In this project, the lexer sends token data as JSON so the web page can display results in a table.

Tokens, Lexemes, and Patterns

Each token connects a piece of text to a category.

Term Meaning Project Example
Lexeme The actual text found in the source code. while, x, 10
Token The category assigned to a lexeme. KEYWORD, IDENTIFIER
Pattern The rule used to recognize a lexeme. Letters form identifiers, digits form numbers.

Project Workflow

The project connects a web interface to a C++ lexer server.

1

User enters code in the browser.

2

JavaScript sends a POST request to /analyze.

3

The C++ backend extracts the code field.

4

The lexer scans the input and builds token objects.

5

The browser displays lexemes and token categories.

Implementation Details

The lexer uses direct scanning and helper functions.

Identifier Handling

Reads letters, digits, and underscores. Then checks if the lexeme is a keyword.

Number Handling

Recognizes integers, decimal numbers, and exponent-style numeric constants.

Operator Handling

Supports single operators and combined operators like >=, ==, and <<.

JSON Response

Returns token objects with lexeme and type fields for the frontend table.

Programming Language Used

The core lexer is implemented in C++.

C++ was used for the backend tokenizer because it gives direct control over character scanning, string handling, and token creation.

The frontend uses HTML, CSS, and JavaScript to provide an interactive interface.

Results

The project successfully identifies common lexical categories.

KEYWORDif, else, while, return, int
IDENTIFIERvariable and function-like names
NUMERIC_CONSTANTinteger, decimal, and exponent numbers
OPERATOR=, +, -, *, /, >=, ==
SPECIAL_CHARbrackets, commas, semicolons, colons
UNKNOWNcharacters outside the lexer rules

Conclusion

This project demonstrates the first stage of compiler design.

The lexical analyzer scans source code, separates it into lexemes, classifies each lexeme into a token type, and presents the results through a simple frontend.

By combining C++ backend logic with a browser interface, the project makes compiler concepts visible and easier to test.
